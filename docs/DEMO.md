# 答辩演示脚本（5 分钟）

> 目标：5 分钟内让评委看到「真实模型 + 真实大模型 + 真实检索 + 真实兜底」四件事同时在跑，
> 并且能看到代码层面的工程判断，而不只是「点一下有结果」。

## 0. 演示前 30 秒准备

```bash
# 双击项目根目录的 start_server.bat，等窗口出现：
#   Uvicorn running on http://127.0.0.1:8010
```

打开浏览器访问 `http://127.0.0.1:8010`。

**如果现场网络不通 / Key 配额用完**，症状与 Agent 可展示离线规则流程；本地眼底模型有权重时仍可运行。
化验单与多模态综合分析依赖在线模型，不可用时展示明确提示，不能宣称这些步骤也能离线识别。

## 1. 能力矩阵（20 秒）

打开 `http://127.0.0.1:8010/api/health`。

要讲的一句话：

> 这一个接口把所有能力当前到底是「真跑」还是「降级」都摊开了：
> 眼底模型在不在、大模型通不通、向量检索建没建起来、地图 Key 有没有。
> 答辩现场最怕的是某个能力悄悄掉了还看不出来，所以先把它做成可观测的。

看这几个字段：

| 字段 | 期望 | 含义 |
|---|---|---|
| `fundus_mode` | `model` | EfficientNet-B3 真推理，不是演示模式 |
| `llm_model` | `deepseek-v4-flash-ga-260731` | 主模型（DeepSeek-V4-Flash 正式版，有免费额度） |
| `llm_vision_model` | 默认与 `llm_model` 相同 | 带图请求用的模型；图片支持待首次联调确认，可用 `ARK_VISION_MODEL` 拆开 |
| `capabilities.rag_vector` | `false` | **故意关掉的**，见第 3 步的讲法 |
| `capabilities.mcp_server` | `true` | MCP 工具层可用 |
| `auth.scheme` | `JWT-HS256` | 鉴权方案 |

`rag_vector: false` 是这段的小高潮，别跳过去——**主动解释一个 `false` 比展示一堆 `true` 更能体现工程判断**（见第 3 步「向量通道为什么关掉」）。

## 2. 眼底糖网筛查（60 秒）— 核心亮点

进入工作台 → **AI 扫描分诊** → 上传一张眼底图。

要讲的三件事：

1. **真实模型**：EfficientNet-B3，5 分类（DR 0–4 国际分级），
   DR 合并集 test 508 张：QWK **0.8958**、准确率 **76.57%**（`evals/eval_fundus.py` 可复现）。
   要主动补一句：中间两级（1/3 级）召回只有 0.53 / 0.58，这两级模型判别力弱，报告里会提示医生复核——
   主动说短板比被评委问出来强。
2. **可解释**：同时输出 Grad-CAM 热力图，叠加在原图上——
   评委会问「模型凭什么」，热力图就是答案，落在出血点/微血管瘤上。
3. **落到科室**：分级不是终点，系统把 DR 分级映射到「内分泌科/眼科 + 复查周期 + 紧急度」。

> 讲法：不要说「我们做了个分类模型」。要说
> 「分级结果必须能落到就医动作上，否则用户拿到一个 3 级不知道下一步干嘛」。

## 3. 症状分诊（60 秒）— 展示模型 + 检索 + 分级

工作台 → **症状分诊**，输入（**直接念出来**）：

> 「胸口闷痛，放射到左肩，出冷汗」

等约 10–12 秒（这个时间要主动说，别让评委以为卡住）：

> 单次大模型调用大约 10 秒，因为要跑完整结构化输出，不是简单问答。
> 所以我们做了两件事：前端有明确 loading 状态；后端有硬超时 + 降级链。

期望结果：

| 字段 | 值 |
|---|---|
| 科室 | 急诊科（立即就医） |
| 紧急度 | **红色 · 立即急诊就医，建议拨打 120** |
| 疑似方向 | 急性冠脉综合征 60% / 不稳定型心绞痛 25% |
| 知识库命中 | 胸口闷痛、放射至左肩、出冷汗 |

要讲的三层：

> **第一层**：大模型做结构化输出，不是自由文本——科室、紧急度、疑似方向带置信度、建议检查、红旗信号，前端直接可渲染。
>
> **第二层**：RAG 召回。知识库 64 条医学条目，关键词 + bigram + 双向同义词。两套指标：
> **golden 集 recall@3 = 1.00**（但这批句子是边看结果边修的，只能当回归测试用），
> **盲测 hold-out recall@3 = 0.91**（80 句，写的时候不知道检索结果）——后者才是能拿去讲的数。
>
> **第三层**：分级不是模型随口说的，是「红色/橙色/黄色/绿色」四档确定性映射，有单测覆盖（`tests/test_triage.py`）。

**关键一句**（评委会记住的）：

> 用户说「膝盖疼」，知识库关键词写的是「膝盖痛」。
> 单向同义词扩展是查不到的——键是「关节痛」，用户输入里没有这个词。
> 所以我们做成双向：命中任一值，把规范词也补进查询。

**向量通道为什么关掉**（这是最能拿分的一段，因为大部分项目只会往上加）：

> `rag_vector` 是 `false`，我们主动关的。原来接了 fastembed + bge-small-zh 做语义召回，
> 但用盲测集做消融发现：关掉它，recall@3 一点不掉（0.912 vs 0.912）。
> 再往下查原因——「蹲下去站起来眼前一黑」这句话，全库最相似的条目是「呕血 · 便血 · 黑便」，
> 相似度 0.507，而真正的正样本「心口像被压了块石头 → 胸痛」也只有 0.50。
> **正负样本完全重叠，这个模型在我们的短句场景里根本分不开。**
> 更危险的是它会给出自信的错误答案：体位性低血压被答成消化道出血。
>
> 所以我们把阈值提到 0.55，让它只在「关键词完全没命中」时兜底，然后干脆默认关掉——
> 省下 90MB 模型和 1.6 秒冷启动。留一个不工作的组件在架构图里好看，
> 但它会在真实的医疗场景里把人引到错误的科室。

## 4. 降级链（40 秒）— 现场最能打的证据

**方式 A（推荐，不用断网）**：把 `.env` 里 `ARK_API_KEY` 改成空值，重启，再点一次症状分诊。

**方式 B**：拔网线 / 关代理。

期望表现：

- 依然返回完整卡片：科室、紧急度、疑似方向、建议检查、红旗信号，一个不少；
- 卡片顶部有明确标注：`AI 分析暂不可用，以下是基于内置医学知识库的规则匹配结果`；
- 响应时间从 10 秒降到毫秒级。

要讲的一句话：

> 医疗场景里「转圈然后报错」是最差的结果。
> 我们做了三级：大模型正常 → 规则引擎（基于同一份知识库，不打折）→ 全科兜底卡。
> 任何一档返回的都是可渲染结构，前端代码不用改。

代码位置（如果评委要翻）：`backend/ai_analysis.py` 的 `_rule_based_symptom()`，
以及 `api/routes/screening.py` 里的 `asyncio.wait_for(...)` 硬超时。

## 5. 安全与限流（40 秒）

**限流**：在症状分诊页**快速连点两次**提交。

期望第二次立即返回：

```
操作过快，请 1.2 秒后再试   （HTTP 429, code=RATE_LIMITED）
```

要讲的三点：

> 1. **防连点 + 配额**：同接口最短间隔 1.5 秒，每用户每分钟 8 次。前端点了没反应就狂点，是最常见的事故来源。
> 2. **PII 不进推理链路**：手机号、身份证、邮箱在送模型之前就脱敏。这里踩过一个坑——身份证 18 位里含 11 位连续数字，如果先跑手机号正则，会把身份证从中间咬掉一段，身份证规则就再也匹配不上。所以顺序必须是身份证优先。
> 3. **输出护栏只标注不改写**：命中「确诊为/可以停药/根治」这类越界词，标注 `guard: review` 并附命中词，**但不篡改原文**。悄悄改掉模型说的话，比如实标注危险得多。

**审计**：`backend/medtriage.db` 里的 `audit` 表，每条带 `request_id`，
和响应头 `X-Request-Id` 对应，可全链路追溯。

## 6. 代码质量（40 秒）— 留给提问环节

如果评委问「你们怎么保证改了不坏」：

```bash
cd backend
python -m pytest tests/ -q          # 以实际输出为准（数量随版本增长）
python evals/run_evals.py           # golden recall@3 = 1.00
python evals/run_blind.py           # 盲测 recall@3 = 0.989（回归口径，见 EVAL.md §2；向量通道默认关，消融显示 N/A）
```

| 证据 | 位置 |
|---|---|
| 74 个单测（分级/RAG/护栏/鉴权/接口契约/危险误召回） | `backend/tests/` |
| CI 门禁（golden≥0.90 且 blind≥0.80 且 Δ向量≥0） | `.github/workflows/ci.yml` |
| 架构与降级链说明 | `docs/ARCHITECTURE.md` |
| 评测报告（含盲测批次与消融，自动生成） | `docs/EVAL.md` |
| 实际达成 vs 计划的差距清单 | `PLAN-95.md` §7 |
| 前端 TS 严格模式，`any` 零处 | `frontend/` |

> 特别说明两点：
>
> **一、CI 里的评测原本写着 `|| true`**——指标再差也永远绿。我们把它改成了真阈值断言，不达标就让 CI 红。
> 一个永远通过的测试等于没有测试。
>
> **二、门禁同时卡 golden 和盲测**，并且检查两者差距。只看 golden 会鼓励「照着例句调参」，
> golden 涨、盲测跌就是过拟合，CI 直接红。这条规则是被我们自己坑出来才加的——
> 这一轮我确实一度把 golden 调到 1.00，盲测只有 0.60。

## 可能被追问的问题与答法

**Q：大模型 10 秒是不是太慢？**
A：是。所以做了三件事——硬超时 45 秒走降级、规则引擎兜底、前端明确 loading 且可取消。
如果做流式输出能压到首字 1–2 秒，但结构化 JSON 需要完整返回才能渲染卡片，
所以我们选择「要么完整卡片，要么快速给规则结果」，不做半截输出。

**Q：recall@3 是多少？怎么提升？**
A：分两个数讲，不要混。
**golden 集 1.00（50/50）**——但这批句子是边看检索结果边修的，它只能证明「这些句子没退化」，
不能拿来宣称泛化能力，讲的时候必须自己先说破。
**盲测 hold-out 0.91（73/80）**——写句子时不知道检索结果，这才是能讲的数。

剩下 7 条未命中我逐条看过，**一半是知识库缺条目**（「小腿抽筋」「皮肤长痣」「磨牙」这两三个词全库都没有），
另一半是排序问题（「看东西有黑点飘」被「卒中预警」抢走，因为「黑点」和卒中条目有字面重叠）。
前者补条目收益最大，后者要引入专门的「视觉症状」特征。

> 如果评委追问「你怎么保证 0.91 不是调出来的」：
> 答「所以 CI 里同时卡两个阈值，并且检查两者差距超过 0.15 就红。
> 这条规则是被我自己坑出来才加的——这一轮我确实一度把 golden 调到 1.00，盲测只有 0.60。」

**Q：为什么手写 JWT 不用 PyJWT？**
A：为了不引额外依赖，同时控制 payload 字段（sub/iat/exp/jti）。
关键是 `hmac.compare_digest` 做恒定时间比对，避免签名校验的时序侧信道；
登录失败路径也走一次哈希，避免「用户名是否存在」被时间差探测出来。
不过 `mcp` 装了 PyJWT，如果团队更倾向成熟库，替换成本很低。

**Q：单机 SQLite 能扛住吗？**
A：演示规模够用，且开了 WAL 模式（并发读不阻塞写）。
生产要换 PostgreSQL，但所有 SQL 都集中在 `db.py`，替换面很小。

**Q：这个项目最让你印象深刻的一个 bug？**
A：`mask_pii` 的顺序问题。手机号正则 `1[3-9]\d{9}` 会从 18 位身份证中间咬走 11 位数字，
替换成 `[手机号]` 之后身份证规则就再也匹配不上——身份证号就这么漏出去了。
这个 bug 是写单测的时候才发现的，手点根本发现不了，因为输出看起来「确实脱敏了」。
