# MedTriage 社会价值与落地规划

MedTriage 面向眼底筛查结果理解、化验报告解读和就医信息查询，将图像、指标与症状连接到科室、就诊准备和医院导航。

## 目标用户与场景

| 用户或场景 | 提供的服务 |
|---|---|
| 需要理解报告的个人 | 结构化指标、通俗解读、来源与后续就医信息 |
| 糖尿病眼病风险关注人群 | 眼底初筛参考、图像质量提示、双眼信息整理 |
| 社区健康服务与体检场景 | 辅助整理筛查信息、风险提示与转诊材料 |
| 健康管理人员 | 在授权前提下辅助解释信息、减少重复整理工作 |

## 社会价值

系统把“看不懂报告”和“不知道下一步去哪看”连接起来，以清晰的页面、可点击来源与就诊准备帮助用户整理信息。
专用眼底模型在本地执行，网络条件受限时仍可提供相应本地能力；症状与 Agent 的知识库规则降级为基础信息服务提供连续性。

## 落地路径

1. 以现有公网演示与可复现源码开展功能体验，观察上传完成率、报告理解与导航路径。
2. 在获得授权和专业复核条件后开展可用性试点，记录人工复核耗时、误分类型、设备差异与用户反馈。
3. 根据试点结果评估机构服务、健康管理配套或按筛查量服务的可行性，并完善相应质量与数据治理流程。

## 服务与成本设计

本地眼底推理与云端文本/视觉任务分开配置，可按场景选择服务组合。用量页记录 token 并提供估算，实际费用以服务商账单为准。
落地成本还应计入设备、人工复核、运维、专业内容维护和数据保护。机构合作、定价与收益属于待验证的规划，不作为已实现业绩。

## 数据与适用范围

个人记录按账号隔离，文字采用脱敏处理。专用眼底页面在本地模型可用时进行本地推理，化验与聊天识图按配置调用视觉服务；上传图片应按对应授权与隐私要求使用。
系统定位为筛查参考和就医信息导航，实际诊疗由医生决定。模型指标、图像质量与来源覆盖情况见技术与评测说明，应用推广应以相应专业评审和实际验证为依据。
