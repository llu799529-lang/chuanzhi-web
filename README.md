# 传智web · MedTriage 多模态智能分诊与就医导航系统

**[优先在线体验](http://101.37.180.16) · [代码仓库](https://github.com/llu799529-lang/chuanzhi-web) · [图文操作手册](02_作品介绍与操作手册.pdf) · [技术说明书](03_技术说明书.pdf)**

MedTriage 将眼底彩照、化验单和症状描述连接成一条完整的健康信息服务流程：上传或描述信息，获取结构化筛查参考，理解关键指标，再了解就诊科室与附近医院。

在线体验使用服务器已配置的服务，登录或注册后即可体验相应功能，无需先安装本地依赖或个人填写 API Key。

## 项目亮点

| 亮点 | 实现与体验 |
|---|---|
| 专用眼底筛查 | EfficientNet-B3 本地五级分类、水平翻转 TTA 与 Grad-CAM 热力图，支持图像质量提示 |
| 专业阅片与双眼筛查 | 原图、CLAHE 增强、绿色通道、热力层叠加、同步放大与双眼较重等级汇总 |
| 化验单结构化与核验 | 视觉模型抽取项目、数值、单位和参考范围；规则核验提示需人工核对的项目，保留原始识别值 |
| 可观察的 Agent | 原生 Function Calling、SSE 流式输出、工具状态、规则规划、自检和有限报告修复 |
| 可追溯的知识检索 | 医学知识库、双向同义词与否定处理、报告内联引用和来源链接 |
| 筛查到就医的闭环 | 历史记录、多模态综合分析、科室建议、就诊准备、地图与医院导航 |

系统同时提供急症规则闸门、文字脱敏、账号隔离、限流、超时控制和明确标注的离线降级。

### 从模型结果到可对照的阅片体验

本地眼底模型输出五级概率和 Grad-CAM，页面继续提供图像质量提示、CLAHE 增强、绿色通道、热力层调节与同步放大。双眼模式分别保留左右眼信息，汇总较重等级，并单独处理不可评估照片。

这条链路把模型输出、图像查看和就医参考连接起来；切换阅片视图只改变显示，不改写分级与概率。

### 结构化化验单还有数值核验

视觉识别之后，规则继续检查单位、参考区间、数量级、小数点疑点和异常箭头的一致性。需要核对的项目带提示，原识别值保留，并可回看原单。

数值核验不额外调用模型，让数据整理、风险提示和人工核对能够在同一张报告中完成。

### Agent 的工具、证据与自检过程可见

历史、图片、知识检索、辅助评估、医院检索和追问由工具执行；SSE 让页面展示工具状态和报告进度。报告引用连接到真实知识条目，自检核对工具结果，并对符合条件的问题进行最多一次定向重写。

模型决策、规则规划、证据引用和结果核对各有明确职责，用户可以沿着报告查看对应信息。

### 多个入口共享同一套业务能力

网页接口、Agent 与独立 MCP Server 复用模型、检索、规则和记录模块。分层、循环依赖、记录写入边界和前后端接口对应关系由测试检查，形成可验证的架构约束。

## 建议体验流程

1. 打开 [公网网站](http://101.37.180.16)，登录或注册账号。
2. 在“使用指南”了解上传方法；在眼底页选择示例 A，查看分级、概率、图像质量与热力图。示例 B 用于体验失焦重拍提示。
3. 在“专业阅片”切换底图、调节热力层、并排观察；双眼筛查可分别上传左右眼照片。
4. 在化验单页选择合成示例，查看分类表、逐项解读和数值核对标记；也可描述症状并观察工作台工具调用过程。
5. 查看个人历史、多模态综合分析和就医导航。完整配图步骤见 [操作手册](02_作品介绍与操作手册.pdf)。

示例化验单为合成数据；所有结果用于筛查与就医信息参考，需由医生结合实际情况确认。

## 技术架构

```text
Vue 3 + TypeScript + Pinia + Vue Router + TanStack Query
                    │ 同域 REST / SSE
FastAPI HTTP 层 → 业务编排 → Agent / 模型 / RAG / 安全规则
                    │
SQLite 记录与会话 · 本地 EfficientNet-B3 · 火山方舟文本/视觉服务
                    │
独立 stdio MCP Server 复用相同业务能力
```

前端构建由后端同进程托管。`api/` 负责协议与鉴权，业务模块复用到 HTTP、Agent 和 MCP；`records.py` 统一处理记录写入与脱敏。

目录与数据流见 [架构说明](docs/ARCHITECTURE.md)，AI 技术方案见 [技术说明书](03_技术说明书.pdf)。

## 获取代码与运行

### 下载源码和权重

安装 Git、Git LFS 后执行：

```bash
git lfs install
git clone https://github.com/llu799529-lang/chuanzhi-web.git
cd chuanzhi-web
git lfs pull
```

仓库包含前端源码、当前 `frontend/dist`、后端、测试、资料和 Git LFS 模型文件。仅运行已有构建时，无需先安装 Node.js。

### Windows 本地运行

1. 准备 Python 3.10+，首次安装运行与图像质量检测依赖：

   ```bash
   python -m pip install -r backend/requirements.txt numpy
   ```

2. 复制根目录 `.env.example` 为 `.env`，在本机填写服务配置。API Key 仅在服务端使用。
3. 双击 **01_双击启动MedTriage.bat**，保持启动窗口打开；服务就绪后浏览器自动打开。
4. 首次从公开仓库运行时，在登录页注册账号。配置由服务器统一提供，个人记录按账号隔离。

以后正常运行直接双击启动脚本，已有可用依赖会复用。**04_检查运行环境.bat** 提供只检查、不安装的入口。详情见 [运行说明](00_先读我_运行说明.md)。

### 通用启动

在项目根目录准备好 `.env` 后：

```bash
python -m pip install -r backend/requirements.txt numpy
# 需要本地真实眼底推理时安装
python -m pip install torch torchvision
cd backend
python -m uvicorn main:app --host 127.0.0.1 --port 8010
```

本地访问 `http://127.0.0.1:8010`。需要修改或重建前端时，在 `frontend` 目录执行 `npm ci`、`npm run build`。

## 环境配置

| 变量 | 作用 |
|---|---|
| `ARK_API_KEY` | 火山方舟服务鉴权，启用在线文本、视觉及综合分析 |
| `ARK_MODEL` | 文本模型，默认 `deepseek-v4-flash-ga-260731` |
| `ARK_VISION_MODEL` | 视觉模型，默认 `deepseek-v4-1-flash-economy-261017` |
| `LLM_THINKING` | 思考参数配置，默认 `off` |
| `LLM_ALLOW_PAID_FALLBACK` | 自动付费模型切换开关，默认 `0` |
| `AMAP_JS_KEY` / `AMAP_JS_SEC` | 地图页面配置 |
| `AMAP_API_KEY` | 后端医院 POI 检索配置 |
| `FUNDUS_WEIGHTS` | 可选的眼底权重自定义路径 |
| `MEDTRIAGE_DATA_DIR` | 数据库目录 |
| `JWT_SECRET` | 可选的服务器登录签名配置 |

其他选项见 `.env.example` 与 [配置说明](05_代码仓库与环境配置说明.md)。模型额度和费用以配置账号控制台为准。

公开仓库提供环境模板，不包含真实 API Key、JWT 私钥或用户数据库。访问公网网站使用服务器配置；下载源码在本地运行时，需要自己的环境配置。
